# Per-module coverage reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Post a comment on every pull request showing coverage for the modules whose own tests ran, plus per-file coverage for the files that pull request changed.

**Architecture:** One Tuist setting makes the CI run collect coverage at all. A Python script extracts two JSON documents out of the existing result bundle — the coverage report and the list of test targets that executed — intersects them to decide which modules to list, and renders markdown. A bash mise task feeds it the pull request's changed files from the GitHub API and posts the result as a single sticky comment.

**Tech Stack:** Tuist 4 (`ProjectDescription`), Python 3 standard library only (`unittest` for tests), bash, `gh`, `xcrun xccov`, `xcrun xcresulttool`.

**Spec:** `docs/superpowers/specs/2026-09-13-coverage-reporting-design.md`

## Global Constraints

- **Swift comments are `//` only.** Never `///`, never `/** */`. See `AGENTS.md`.
- **Comment only what is exceptional.** Do not restate what the code says. See `AGENTS.md`.
- **Python: standard library only.** No new tools, no `pip install`. `fastlane/metadata_lint.py` and `mise/scripts/attribute_blank_lines.py` are the two scripts to match for style — module docstring, `#!/usr/bin/env python3`, argparse.
- **CI treats warnings as errors**, and `ci:lint` runs `swiftformat --lint` and `swiftlint --strict`.
- **Commit messages are conventional commits** (`feat:`, `fix:`, `chore:`, `docs:`, `test:`). `lint-pr.yml` enforces this on the pull request title.
- **Never run `tuist test` without `--no-binary-cache` locally.** Cached binaries bake the building machine's `#filePath`, which breaks fixture-path tests for environmental reasons.
- The bundle CI produces is `test-unit.xcresult` at the repository root.
- The sticky comment marker is exactly `<!-- coverage-report -->`.

#!/usr/bin/env python3
"""Report per-module code coverage for the modules whose own tests ran.

Reads an .xcresult bundle and prints a markdown comment body. A module is listed only
when its own test target executed: coverage measured sideways through somebody else's
suite is not something a reviewer can act on, and printing it invites reading a shared
module's number as if its own tests had earned it.

The numbers themselves are still suite-wide - the whole suite runs as one scheme, so a
listed module's percentage counts lines reached by every test that ran, not only its own.
See docs/superpowers/specs/2026-09-13-coverage-reporting-design.md.
"""

from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path

MARKER = "<!-- coverage-report -->"


@dataclass(frozen=True)
class ModuleRow:
    name: str
    covered: int
    executable: int


def percent(covered: int, executable: int) -> str:
    if executable == 0:
        return "n/a"
    return f"{covered / executable * 100:.1f}%"


def module_for_target(target_name: str) -> str:
    return Path(target_name).stem


def module_for_test_bundle(bundle_name: str) -> str | None:
    suffix = "Tests"
    if not bundle_name.endswith(suffix):
        return None
    return bundle_name[: -len(suffix)] or None


def module_rows(coverage: dict, executed_bundles: list[str]) -> list[ModuleRow]:
    tested = {
        module
        for module in (module_for_test_bundle(name) for name in executed_bundles)
        if module
    }

    rows = [
        ModuleRow(
            module_for_target(target["name"]),
            target["coveredLines"],
            target["executableLines"],
        )
        for target in coverage.get("targets", [])
        if module_for_target(target["name"]) in tested
    ]

    return sorted(rows, key=lambda row: row.name)
```

@dataclass(frozen=True)
class FileRow:
    path: str
    covered: int | None
    executable: int | None


def instrumented_modules(coverage: dict) -> set[str]:
    return {module_for_target(target["name"]) for target in coverage.get("targets", [])}


def relative_path(absolute: str, repo_root: Path) -> str | None:
    try:
        return str(Path(absolute).relative_to(repo_root))
    except ValueError:
        return None


def changed_source_files(changed: list[str], instrumented: set[str]) -> list[str]:
    kept = []
    for path in changed:
        parts = Path(path).parts
        if len(parts) < 3 or parts[0] != "Modules" or not path.endswith(".swift"):
            continue
        # Membership of the instrumented set is what excludes test and support modules, so there
        # is no second list of module names here to drift from Module.codeCoverageTarget.
        if parts[1] not in instrumented:
            continue
        kept.append(path)

    return sorted(set(kept))


def file_rows(
    coverage: dict, changed: list[str], listed: set[str], repo_root: Path
) -> list[FileRow]:
    measured: dict[str, tuple[int, int]] = {}
    for target in coverage.get("targets", []):
        if module_for_target(target["name"]) not in listed:
            continue
        for entry in target.get("files", []):
            path = relative_path(entry["path"], repo_root)
            if path:
                measured[path] = (entry["coveredLines"], entry["executableLines"])

    rows = []
    for path in changed:
        if path in measured:
            covered, executable = measured[path]
            rows.append(FileRow(path, covered, executable))
        else:
            rows.append(FileRow(path, None, None))

    return rows
```

```python
def render(modules: list[ModuleRow], files: list[FileRow]) -> str:
    lines = [MARKER, "", "## Coverage", ""]

    if not modules:
        lines += [
            "No modules were tested in this run - selective testing found nothing whose",
            "fingerprint changed.",
            "",
        ]
        return "\n".join(lines)

    lines += ["| Module | Coverage | Lines |", "| --- | ---: | ---: |"]
    lines += [
        f"| {module.name} | {percent(module.covered, module.executable)} "
        f"| {module.covered}/{module.executable} |"
        for module in modules
    ]
    lines += [
        "",
        "Only modules whose own tests ran are listed, and the numbers are suite-wide.",
    ]

    if files:
        lines += [
            "",
            "### Files changed in this pull request",
            "",
            "| File | Coverage | Lines |",
            "| --- | ---: | ---: |",
        ]
        for entry in files:
            if entry.covered is None:
                lines.append(f"| {entry.path} | not measured | |")
            else:
                lines.append(
                    f"| {entry.path} | {percent(entry.covered, entry.executable)} "
                    f"| {entry.covered}/{entry.executable} |"
                )

    lines.append("")
    return "\n".join(lines)
```

```python
def read_coverage(bundle: Path) -> dict:
    result = subprocess.run(
        ["xcrun", "xccov", "view", "--report", "--json", str(bundle)],
        capture_output=True,
        text=True,
        check=True,
    )
    return json.loads(result.stdout)


def read_executed_bundles(bundle: Path) -> list[str]:
    result = subprocess.run(
        [
            "xcrun", "xcresulttool", "get", "test-results", "tests",
            "--path", str(bundle), "--format", "json",
        ],
        capture_output=True,
        text=True,
        check=True,
    )

    return [
        child["name"]
        for plan in json.loads(result.stdout).get("testNodes", [])
        for child in plan.get("children", [])
        if child.get("nodeType") in {"Unit test bundle", "UI test bundle"}
    ]


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--bundle", type=Path, required=True)
    parser.add_argument("--repo-root", type=Path, required=True)
    parser.add_argument(
        "--changed-files",
        type=Path,
        help="file listing the pull request's changed paths, one per line",
    )
    args = parser.parse_args()

    # No bundle means xcodebuild never ran. run_tests.sh already treats that as a legitimate
    # outcome, and the comment still has to be rewritten to say so.
    if not args.bundle.exists():
        print(render([], []), end="")
        return 0

    coverage = read_coverage(args.bundle)
    modules = module_rows(coverage, read_executed_bundles(args.bundle))

    changed = []
    if args.changed_files and args.changed_files.exists():
        changed = args.changed_files.read_text().split()

    listed = {module.name for module in modules}
    files = file_rows(
        coverage,
        changed_source_files(changed, instrumented_modules(coverage)),
        listed,
        args.repo_root,
    )

    print(render(modules, files), end="")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### Task 6: Post the sticky comment from CI

**Files:**
- Create: `mise/tasks/ci/coverage`
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `mise/scripts/coverage_report.py` from Task 5.
- Environment: `COVERAGE_PR_NUMBER` (the pull request number), `GITHUB_REPOSITORY` and `GH_TOKEN` (both already provided by Actions; `GH_TOKEN` is set at workflow level in `ci.yml`).

- [ ] **Step 1: Write the task**

Create `mise/tasks/ci/coverage`:

```bash
#!/usr/bin/env bash
#MISE description="Comment per-module coverage on the pull request"
set -euo pipefail

: "${COVERAGE_PR_NUMBER:?not set - this task only has somewhere to comment on a pull request}"

changed="$(mktemp)"
trap 'rm -f "$changed"' EXIT

# GitHub rather than `git diff`: actions/checkout fetches to depth 1, so neither the base commit
# nor origin/main is an object this runner can be relied on to have - they survive here only
# because the checkout uses `clean: false`, which is an accident of a reused workspace. The API
# needs no git objects, and its per-file status drops deletions without a second rule.
gh api --paginate "repos/${GITHUB_REPOSITORY}/pulls/${COVERAGE_PR_NUMBER}/files" \
  --jq '.[] | select(.status != "removed") | .filename' > "$changed"

body="$(python3 "$MISE_PROJECT_ROOT/mise/scripts/coverage_report.py" \
  --bundle "$MISE_PROJECT_ROOT/test-unit.xcresult" \
  --repo-root "$MISE_PROJECT_ROOT" \
  --changed-files "$changed")"

# One comment, rewritten on every push. A column of superseded coverage tables is worse than no
# table at all - only the newest describes the head being reviewed.
#
# Taken with a parameter expansion rather than `head -1`, which would close the pipe under
# `set -o pipefail` and fail the step on any pull request with more than one page of comments.
ids="$(gh api --paginate "repos/${GITHUB_REPOSITORY}/issues/${COVERAGE_PR_NUMBER}/comments" \
  --jq '.[] | select(.body | contains("<!-- coverage-report -->")) | .id')"
id="${ids%%$'\n'*}"

if [ -n "$id" ]; then
  gh api -X PATCH "repos/${GITHUB_REPOSITORY}/issues/comments/${id}" -f "body=${body}" > /dev/null
else
  gh api -X POST "repos/${GITHUB_REPOSITORY}/issues/${COVERAGE_PR_NUMBER}/comments" \
    -f "body=${body}" > /dev/null
fi

echo "Coverage comment updated on #${COVERAGE_PR_NUMBER}."
```

## Self-Review

**Spec coverage:**

| Spec section | Task |
| --- | --- |
| Collecting coverage (`Workspace.swift`) | 1 |
| Deciding which modules are listed | 2 |
| The report — modules table | 2, 4 |
| The report — changed files, not-measured rendering | 3, 4 |
| Posting — sticky comment, marker, missing bundle | 5, 6 |
| The JSON in between (extraction/rendering seam) | 3, 4, 5 — `render` takes only dataclasses, never a bundle |
| Testing — `unittest`, wired into `ci:lint` | 2 |

**Deviation from the spec, deliberate:** the spec describes writing the extracted structure to a JSON file. That file has no reader — a future threshold gate is out of scope — so writing it would be an unused artifact. The requirement behind it is that rendering never touches a result bundle, and that holds: `render` takes `list[ModuleRow]` and `list[FileRow]` and nothing else, so a gate can consume the same dataclasses without re-parsing anything. Add `--json` when something needs it.

**Type consistency:** `ModuleRow(name, covered, executable)` and `FileRow(path, covered, executable)` are used with those field names in Tasks 2, 3, 4 and 5. `module_for_target` is used in `module_rows`, `instrumented_modules` and `file_rows` with the same signature. `percent` is called only from `render`. `MARKER` is defined in Task 2 and matched literally by the `gh` filter in Task 6.

**One known limitation, accepted:** `changed_source_files` drops a changed file whose module is absent from the coverage report. Under selective testing a changed module is always selected, so this only bites if a module is instrumented but excluded from the build for some other reason.
